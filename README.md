# freeweb-resolver

Локальный резолвер, который позволяет обычному браузеру (Safari, Chrome — без
расширений) открывать децентрализованные домены `.eth` (ENS + IPFS) так же,
как обычные сайты — с валидным замком в адресной строке.

Прототип. Не production-хардненный код, обкатан только вручную, тестов нет.
Используется на свой страх и риск.

## Как это работает

```
браузер → локальный DNS (перехватывает .eth/.test) → 127.0.0.1
        → локальный HTTPS-шлюз (сертификат от локального CA)
        → резолвинг ENS-имени в Ethereum (JSON-RPC)
        → contenthash → запрос к локальной IPFS-ноде (kubo)
        → настоящий контент сайта отдаётся браузеру
```

Три отдельных фоновых процесса:
1. `resolver` (этот репозиторий) — DNS-резолвер + HTTPS-шлюз.
2. `ipfs daemon` (kubo, ставится отдельно) — забирает контент из сети IPFS.
3. Публичный RPC-эндпоинт Ethereum (по умолчанию `ethereum-rpc.publicnode.com`,
   настраивается флагом) — единственная оставшаяся точка доверия третьей
   стороне, замена на свою ноду не сделана.

## Модель доверия — прочитать перед установкой

Установка создаёт **собственный корневой сертификат (CA)** и добавляет его в
доверенные в системной Связке ключей. Это значит, что операционная система
будет считать сертификаты, подписанные этим CA, легитимными — ровно как
сертификаты настоящих публичных удостоверяющих центров.

Важно: сервер **не** подписывает сертификат на произвольный домен — только на
зоны из списка `--zones` (по умолчанию `test.,eth.`). Проверка на это есть
и в DNS-слое, и отдельно в TLS-слое (после исправления реальной уязвимости,
найденной ревью безопасности: изначально TLS-слой подписывал что угодно —
подробности в истории коммитов). Если ты меняешь код — не убирай эту
проверку в `cert.go` без крайней необходимости, иначе любой локальный
процесс сможет получить доверенный сертификат на произвольный сайт.

## Установка

```sh
./install.sh
```

Полностью автоматизировано: поставит Go и kubo, если их ещё нет, соберёт
резолвер, настроит автозапуск через `launchd` (резолвер и IPFS-нода сами
поднимаются при входе в систему и сами перезапускаются, если упадут —
проверено вживую: `kill -9` на процесс → `launchd` поднимает новый PID за
пару секунд), и в конце попросит пароль **один раз** для двух системных
шагов — добавить CA в доверенные и настроить split-DNS (см. ниже про VPN).

После установки просто открой в браузере:
```
https://vitalik.eth:15443/
```
Порт `:15443` — потому что мы не занимаем привилегированный `443` (см.
раздел про сброс привилегий ниже). Перезагружай Mac когда угодно — всё
поднимется само, руками ничего запускать не нужно.

**Почему split-DNS, а не общий системный DNS:** если у тебя включён VPN,
он обычно и так владеет системным DNS на macOS — общий DNS для всей
системы конфликтовал бы с ним. `/etc/resolver/eth` — это встроенный в
macOS механизм, который работает только для перечисленных зон и вообще не
пересекается с VPN (проверено вживую с активным VPN-туннелем — весь
остальной трафик как ходил через VPN, так и ходит).

## Удаление

```sh
./uninstall.sh
```
Уберёт автозапуск, CA из доверенных и split-DNS-зоны (спросит пароль один
раз). Сам код и IPFS-репозиторий (`~/.ipfs-freeweb`) не трогает.

## Сброс привилегий (для деплоя на портах 443/53)

Сейчас резолвер работает на непривилегированных портах и root не требует
вообще. Когда понадобится слушать 443/53 (чтобы `.eth`-имена открывались
без указания порта), процесс придётся запускать через `sudo`, но он тут же
сам откажется от root: сначала биндит все порты, затем сразу опускает себя
до обычного пользователя (`setgroups`→`setgid`→`setuid`, с проверкой, что
вернуться назад в root уже нельзя) — и вся обработка чужих запросов идёт
уже без каких-либо повышенных прав.

```sh
sudo ./resolver -https-listen 0.0.0.0:443 -dns-listen 0.0.0.0:53 -drop-to-user <твой_юзер>
```

Без `--drop-to-user` запуск от root разрешён, но в лог печатается явное
предупреждение — так безопаснее по умолчанию, но без жёсткого запрета.

## Индикатор в браузере (опционально)

`browser-extension/` — маленькое расширение для Chrome/Edge/Brave, значок
в панели показывает зелёным/оранжевым/красным, живы ли резолвер и IPFS-нода.
Не резолвит и не подменяет ничего сам, только статус. Установка — см.
`browser-extension/README.md`.

## Флаги

Полный список: `./resolver -help`. Основные: `-zones`, `-eth-rpc`,
`-ipfs-gateway`, `-dns-listen`, `-http-listen`, `-https-listen`.

## Известные ограничения

- Изменяемые ссылки (`/ipns/...`) резолвятся не всегда — зависит от
  доступности записи в P2P-сети (DHT), это ограничение самого IPFS, не баг
  этого инструмента.
- RPC на Ethereum — единственная оставшаяся точка доверия третьей стороне.
- Нет установщика/анинсталлера — шаги выше делаются руками.
- Handshake (`.hns`) пока не реализован, только ENS (`.eth`).
